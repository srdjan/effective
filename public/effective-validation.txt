Draft 0.3 specification, October 17, 2026
Language core version 1 specifies references, races, scoped fibers, borrowed handles,
buffered and merged streams, retry schedules, pure codecs, source Layers, and a typed
file service host adapter. The specification requires light-functional-ir version 2.
The effective-lang compiler implements the listed core 1 extensions and emits IR version 2.
The core 1 example is an illustrative source/target pair; the compiler also
accepts its Effective source. The strict target check covers its Effect-TS tab.
Historical counts and compiler checks above apply to their named drafts only.

IR version 2 migration
The effective-lang compiler and independent validator emit and accept version 2.
Version 1 input now produces validation/008. Canonical compiler fixtures and this
site's linked model and log fixture use version 2. The full compiler check passed.

Buffered and merged streams
The compiler accepts bufferStream with a positive safe integer capacity and
mergeStreams with compatible element types. Its validator recomputes active and
deferred channels and rejects an invalid capacity. The emitter uses Stream.buffer
with the suspend strategy and Stream.merge. A runtime test checks deferred
production and per-source order.
The subsequent sections record the remaining core 1 implementation slices.

Races
The compiler accepts race of two compatible Effect values. The validator
recomputes its deferred failure and requirement unions. The emitter calls
Effect.race. A runtime test confirms the losing fiber is interrupted and its
cleanup completes before the result returns. At this milestone, the combined
Ref and race figure still awaited makeRef support.

References
The compiler now accepts Ref<A>, makeRef, getRef, setRef, and updateRef.
The type is invariant in A. The update callback must be pure and return a
compatible A. A runtime test verifies atomic updates under bounded traversal.
The combined Ref and race figure is now implemented source syntax.

FileSystem host adapter
The compiler fixture host-adapter-files declares a Files.read service and
FileReadError. Its TypeScript host provider uses effect/FileSystem and the
Node platform layer. The adapter checks paths and maps package failures to
the declared error. A CLI build with --validate --tsc and a runtime read,
missing-file case, and invalid-path case pass. Other package adapters remain
outside the implemented subset.

Source Layers
The compiler accepts Layer<Services,E,R>, layer(Service, acquire), and
mergeLayers. It checks that an acquisition returns exactly the declared
methods, preserves acquisition failures and requirements, and rejects
overlapping services. provide accepts source Layer expressions. Runtime tests
cover merged providers and an acquisition that needs another service.

Custom retry schedules
The compiler accepts RetrySchedule<E>, retrySchedule with a pure callback,
and retry(job, { schedule: policy }). The independent validator checks the
nominal error input, attempt type, optional millisecond delay, and deferred
failure channels. The emitter uses Schedule.fromStepWithMetadata. A runtime
test confirms one-based attempts, zero-delay retries, and propagation of the
last typed failure when the callback returns None.

Pure source codecs
The compiler accepts Codec<Decoded,Encoded>, codec, decode, and encode.
Both transformations must be pure, and both types must support derived
schemas. Generated code checks inputs and transformed outputs with Effect
Schema and returns None for invalid values. A strict target check and runtime
test cover both directions and an invalid input.

Scoped fibers
The compiler accepts Fiber<A,E>, withFiber, joinFiber, and interruptFiber.
withFiber starts a supervised child from an Effect value and restricts its
handle to direct join or interrupt calls in an inline callback. The child's
service requirements activate when it starts; its failures enter the parent
contract when joined. A runtime test checks explicit interruption and
finalizer completion.

Borrowed opaque handles
A host interface may declare an opaque type and borrow-qualified service
parameters. withResource can acquire that handle. Its use and release callbacks
may pass it directly to qualified host methods or source helpers whose own
borrowed parameters are checked for escape. The checker and independent IR
validator reject returning, capturing, storing, and ordinary argument passing.
A strict host build and runtime test cover acquisition, use, and release.

Draft 0.4 unbounded traversal, October 18, 2026
The spec accepts only the literal option { concurrency: "unbounded" } or a
positive safe integer bound. The compiler checks and independently validates
that option, then passes it to Effect.forEach. No IR wire shape changed, so
light-functional-ir remains at version 2. The runtime regression covers all
jobs starting, input-order results, typed failure, explicit interruption,
scoped finalizers, empty input, and traversal of first-class Effect values.
General heterogeneous Effect.all collection remains outside this slice.

Draft 0.5 heterogeneous Effect collection, October 18, 2026
The source builtin all accepts tuples, records, and arrays whose members are
Effect values. It preserves each result position or key and unions the latent
failure and service sets. A heterogeneous bracket literal needs a contextual
tuple type. The compiler independently validates the builtin type and literal
concurrency option, then emits Effect.all. Target checks and runtime tests
cover tuple and record results, concurrent startup, sibling interruption,
and scoped finalizer completion. The IR wire shape remains version 2.

Draft 0.6 scoped fibers, October 18, 2026
The source builtins scoped and forkScoped add a local scope for first-class
Effect jobs. forkScoped requires an internal Scope capability and accepts only
jobs without typed failures. scoped removes that requirement and closes the
scope after success, failure, defect, or interruption. The compiler checks
and independently validates the requirement channel. A strict target check
and runtime test confirm that a child outlives its spawning fiber while the
local scope remains open and is interrupted when it closes. Raw Scope values
and explicit Scope.close remain deferred. The IR wire shape remains version 2.

Draft 0.7 stream zipping, October 18, 2026
The source builtin zipStreams pairs two Stream values, including those with
different element types. The result carries a tuple element and both streams'
deferred failure and requirement channels. The checker and independent IR
validator enforce that signature. Strict target and runtime tests confirm
deferred production, ordered pairs, shorter-input termination, and peer
interruption with finalizer completion after failure. The IR wire shape
remains version 2.

Draft 0.8 stream concatenation, October 18, 2026
The source builtin concatStreams joins two Stream values sequentially. Its
element type is the union of both inputs' element types, and its deferred
failure and service channels are combined. The checker and independent IR
validator enforce this signature. Strict target and runtime tests confirm
deferred production, left-before-right order, and that a left failure skips
the right stream. The IR wire shape remains version 2.

Draft 0.9 stream flat mapping, October 18, 2026
The source builtin flatMapStreams accepts an outer Stream and an inline pure
callback returning an inner Stream. The checker and independent IR validator
combine the outer and inner deferred failure and requirement channels while
keeping construction pure. Strict target and runtime tests confirm ordered
inner pulls, failure cutoff, and active-inner cleanup on interruption.
Concurrent flatMap and switch behavior remain deferred. The IR wire shape
remains version 2.

Draft 0.10 collection partitioning, October 18, 2026
The source builtin partitionAll accepts a homogeneous array of Effect values
and returns successes and typed failures in separate input-order arrays. The
checker removes typed failures from the active channel while retaining job
requirements. The independent IR validator checks the result shape and
literal concurrency bound. A strict target check and runtime test confirm
that every job runs, both result arrays retain input order, and the bound is
observed. The IR wire shape remains version 2.

Draft 0.11 aggregate validation, October 18, 2026
The source builtin validateAll runs every Effect job in a homogeneous array.
All successes return in input order. On failure, a pure callback wraps every
typed error in one nominal error for the caller's failure contract. The
checker and independent IR validator enforce the callback and concurrency
bound. A strict target check and runtime test cover the success path and
multiple failures under bounded concurrency. The IR wire shape remains
version 2.

Draft 0.12 result collecting, October 18, 2026
The source builtin allResults runs Effect tuples, records, and homogeneous

service requirements, and the literal concurrency bound. A strict target
check and runtime test cover all three shapes and continued sibling work
