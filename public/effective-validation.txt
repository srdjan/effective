Draft 0.3 specification, October 17, 2026
Language core version 1 specifies references, races, scoped fibers, borrowed handles,
buffered and merged streams, retry schedules, pure codecs, source Layers, and a typed
file service host adapter. The specification requires light-functional-ir version 2.
The effective-lang compiler implements the listed core 1 extensions and emits IR version 2.
The core 1 example is an illustrative source/target pair; the compiler also
accepts its Effective source. The strict target check covers its Effect-TS tab.
Historical counts and compiler checks above apply to their named drafts only.

IR version 2 migration
The effective-lang compiler and independent validator emit and accept version 2.
Version 1 input now produces validation/008. Canonical compiler fixtures and this
site's linked model and log fixture use version 2. The full compiler check passed.

Buffered and merged streams
The compiler accepts bufferStream with a positive safe integer capacity and
mergeStreams with compatible element types. Its validator recomputes active and
deferred channels and rejects an invalid capacity. The emitter uses Stream.buffer
with the suspend strategy and Stream.merge. A runtime test checks deferred
production and per-source order.
The subsequent sections record the remaining core 1 implementation slices.

Races
The compiler accepts race of two compatible Effect values. The validator
recomputes its deferred failure and requirement unions. The emitter calls
Effect.race. A runtime test confirms the losing fiber is interrupted and its
cleanup completes before the result returns. At this milestone, the combined
Ref and race figure still awaited makeRef support.

References
The compiler now accepts Ref<A>, makeRef, getRef, setRef, and updateRef.
The type is invariant in A. The update callback must be pure and return a
compatible A. A runtime test verifies atomic updates under bounded traversal.
The combined Ref and race figure is now implemented source syntax.

FileSystem host adapter
The compiler fixture host-adapter-files declares a Files.read service and
FileReadError. Its TypeScript host provider uses effect/FileSystem and the
Node platform layer. The adapter checks paths and maps package failures to
the declared error. A CLI build with --validate --tsc and a runtime read,
missing-file case, and invalid-path case pass. Other package adapters remain
outside the implemented subset.

Source Layers
The compiler accepts Layer<Services,E,R>, layer(Service, acquire), and
mergeLayers. It checks that an acquisition returns exactly the declared
methods, preserves acquisition failures and requirements, and rejects
overlapping services. provide accepts source Layer expressions. Runtime tests
cover merged providers and an acquisition that needs another service.

Custom retry schedules
The compiler accepts RetrySchedule<E>, retrySchedule with a pure callback,
and retry(job, { schedule: policy }). The independent validator checks the
nominal error input, attempt type, optional millisecond delay, and deferred
failure channels. The emitter uses Schedule.fromStepWithMetadata. A runtime
test confirms one-based attempts, zero-delay retries, and propagation of the
last typed failure when the callback returns None.

Pure source codecs
The compiler accepts Codec<Decoded,Encoded>, codec, decode, and encode.
Both transformations must be pure, and both types must support derived
schemas. Generated code checks inputs and transformed outputs with Effect
Schema and returns None for invalid values. A strict target check and runtime
test cover both directions and an invalid input.

Scoped fibers
The compiler accepts Fiber<A,E>, withFiber, joinFiber, and interruptFiber.
withFiber starts a supervised child from an Effect value and restricts its
handle to direct join or interrupt calls in an inline callback. The child's
service requirements activate when it starts; its failures enter the parent
contract when joined. A runtime test checks explicit interruption and
finalizer completion.

Borrowed opaque handles
A host interface may declare an opaque type and borrow-qualified service
parameters. withResource can acquire that handle. Its use and release callbacks
may pass it directly to qualified host methods or source helpers whose own
borrowed parameters are checked for escape. The checker and independent IR
validator reject returning, capturing, storing, and ordinary argument passing.
A strict host build and runtime test cover acquisition, use, and release.
