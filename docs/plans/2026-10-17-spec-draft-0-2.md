# Plan: spec draft 0.2 (R1, R2, D32)

Status: plan, 2026-10-17. A Fable subagent validated it; Opus accepted all 8 findings. Owner of the rules: the user. Compiler: `/Users/srdjans/Code/effective-lang` at commit `fc00ef7` (v0.2.0).

## 1. Purpose

The compiler implements three rules that the spec does not describe yet:

- R1: a primitive type can occur only inside the body of a `type` or `error` declaration. The compiler reports `declaration/013` in all other positions.
- R2: `Brand<{ ... }>` declares a nominal record. A field read and a record update see through the brand. An update keeps the brand.
- D32: `<`, `<=`, `>`, `>=`, `+`, and `-` accept two values of one numeric brand. `+` and `-` give that brand.

This plan changes the spec page and the mini book to describe the rules. It migrates every Effective example to R1, with its Effect-TS tab. It increments the documentation edition from draft 0.1 to draft 0.2. The language core version stays 0.

## 2. Ground truth

The compiler behavior that the text must describe:

- Primitive types: `string`, `int`, `number`, `boolean`, and literal types such as `"paid"` or `1`. `void`, `never`, and `unknown` are exempt.
- R1 covers every position outside type and error bodies: module and local parameters, results, constant annotations, service methods, function types, and type arguments such as `Option<string>`. It also covers `.effi` host interface files.
- Inline records, inline unions, `Option<T>`, `T[]`, tuples, function types, `Effect`, `Stream`, and `Sink` stay legal when their parts are declared names.
- An alias `type Name = string` satisfies R1. An alias is structural, so it gives no identity.
- R2: `Account({ ... })` constructs a nominal record. A plain record literal does not fit `Account` (`type-mismatch/003`). Two nominal records with identical fields are distinct. A match with a record pattern on a nominal record gives `pattern/004`. A nominal record is rejected as the operation record of `withResource`.
- D32: a numeric brand has the base `int` or `number`, after aliases. `*` and `/` reject a brand (`type-mismatch/007`). A string brand rejects `+`. A literal operand needs the brand call: `total + 1` is rejected, `total + Cents(1)` is accepted. An int brand result outside the safe range is a defect, as for `int`.
